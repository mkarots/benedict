How it works

Invite. Onboard. Ask in the thread.

Explicit commands skip the general path. Everything else builds README, metadata, semantic hits, and recent actions, then asks Claude.

01

Invite Benedict

Add the Socket Mode bot to the channel that already owns the work.

/invite @benedict
02

Onboard a checkout

Point it at a directory that already exists on the host. Nothing is cloned from GitHub.

@benedict onboard repo acme/widget
03

Ask the repo

Benedict searches the index, reads the files, and replies in-thread.

@benedict what files handle auth?

Surfaces

One index. Three places to ask.

Slack stays the working surface. MCP is for the editor. The architect channel is for questions that span more than one onboarded repo.

Slack

Channel-scoped agent

Each channel maps to one repository. The thread is the conversation.

  • onboard / offboard / status commands
  • update index · force reindex
  • link notion <url> per channel
  • run_github · run_notion in conversation
MCP

Same brain, in the IDE

Start benedict-mcp. Cursor and Claude Code query onboarded projects over stdio.

  • list_projects
  • get_repository_summary
  • search_code
  • get_recent_actions · ask_benedict
Architect

Cross-project questions

Mark one channel as architect when the answer lives across repos.

  • onboard architect
  • Sees every mapped workspace
  • Same Claude path, wider context
  • For “who owns auth across services?”

Local-first

The code stays on the machine that runs the bot.

Benedict is not a remote GitHub reader and not a hosted product. Onboarding resolves a local checkout, then isolates it per channel. That is the trust model.

  • + Answers from the files on disk, not a guessed clone
  • + Slack history and conversations persist in state.json
  • + GitHub and Notion use host CLIs you already authenticated
  • + MCP reads the same BENEDICT_DATA_DIR as Slack
  • + Open source under MIT. Read it, run it, fork it.
  • − No GitHub API RepoReader. The directory must exist.
  • − No cloud workspace. Bind the operator console to localhost.

Install

On the host that already has the repos.

Open-source. Python 3.10+, uv, a Slack Socket Mode app, and an Anthropic key. Optional: authenticated gh, ntn, and an MCP client.

Clone on GitHub Slack setup

  1. Clone and sync

    Creates the venv and installs the package.

    git clone https://github.com/mkarots/benedict.git
cd benedict && make setup && make sync-dev

  2. Configure

    Process env wins. Missing keys load from .env.

    SLACK_BOT_TOKEN=xoxb-…
SLACK_APP_TOKEN=xapp-…
ANTHROPIC_API_KEY=…

  3. Run

    Then invite the bot and onboard a checkout that exists locally.

    make run
# optional: make mcp
