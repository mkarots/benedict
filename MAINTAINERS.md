# Maintainers

Who maintains Benedict, how decisions are made, and how to become a maintainer.

## Core maintainers

| Name | GitHub | Role |
| --- | --- | --- |
| Michael Karotsieris | [@mkarots](https://github.com/mkarots) | Project lead |

The project lead merges pull requests, cuts releases, and is the contact for security and conduct reports. That matches the `maintainers` field in [`pyproject.toml`](pyproject.toml).

## Decision-making

The project lead reviews and merges pull requests into `main`. CI must pass. How to open a pull request is in [CONTRIBUTING.md](CONTRIBUTING.md).

If people disagree on a change, discuss it on the pull request. If that does not settle it, the project lead decides.

Security reports follow [SECURITY.md](SECURITY.md). Conduct reports follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Do not decide those on a public issue.

## Becoming a maintainer

There is one maintainer today. The current project lead adds new maintainers after a record of useful reviews and contributions.

To be considered:

- Open useful issues or pull requests
- Review other people's work
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md)

A new maintainer is listed in this file. The project lead will say so on the pull request or in a public note.
